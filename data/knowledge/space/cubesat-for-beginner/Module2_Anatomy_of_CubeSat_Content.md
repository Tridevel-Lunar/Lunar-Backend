## 2.1 ทำไมดาวเทียมต้องมี "ระบบย่อย" (Subsystem)

**Hook เปิดเรื่อง:**
> ในโมดูลที่แล้วเราเห็น CubeSat จากข้างนอกแล้ว — กล่องเล็กๆ ลอยอยู่ในอวกาศ แต่ถ้าผ่าออกมาดูข้างใน จะเจออะไร? คำตอบคือ: ไม่มีอะไรที่ทำงานคนเดียวเลยสักส่วนเดียว

**Analogy หลักของโมดูลนี้ (ใช้ตลอดทั้งบท):** ร่างกายมนุษย์
- **Payload** = ประสาทสัมผัส/มือที่ลงมือทำงาน (ตา หู มือที่หยิบจับ) — คือส่วนที่ทำ "ภารกิจ" จริงๆ ของดาวเทียม
- **EPS (Electrical Power System / ระบบไฟฟ้ากำลัง)** = ระบบย่อยอาหารและหัวใจที่สูบฉีดพลังงานไปเลี้ยงทุกส่วน
- **COMM (Communication / ระบบสื่อสาร)** = ปาก+หู ที่คุยกับโลกภายนอก
- **OBC (On-Board Computer / คอมพิวเตอร์ควบคุมบนดาวเทียม)** = สมอง ที่ตัดสินใจว่าเมื่อไหร่ต้องทำอะไร โดยอาศัยข้อมูลที่ส่วนอื่นส่งมาบอก

**ประเด็นสำคัญที่ต้องปลูกฝังตรงนี้:** เหมือนร่างกายที่มือจะหยิบของไม่ได้ถ้าสมองไม่สั่ง และสมองจะสั่งไม่ได้ถ้าตาไม่ส่งภาพมาให้ก่อน — ดาวเทียมก็เช่นกัน ทุก subsystem **ต้องพึ่งพากันจึงจะทำงานได้ครบวงจร** นี่คือ setup ที่จะ pay off ใน 2.3 (data-flow view) และปิดยอดในโมดูล 4 (programming)

*(หมายเหตุสำหรับทีม: ดาวเทียมจริงมักมีมากกว่า 4 ระบบ เช่น ADCS ระบบควบคุมทิศทาง, Structure โครงสร้าง, Thermal ระบบความร้อน — โมดูลนี้ตั้งใจโฟกัสแค่ 4 ระบบหลักที่ผู้เริ่มต้นควรรู้ก่อน ส่วนระบบอื่นค่อยแตะเบาๆ ในโมดูล 3 ตอนพูดถึงสนามแม่เหล็ก/ADCS)*

## 2.2 รู้จักทีละระบบ

### 🧠 OBC — สมองกลาง (On-Board Computer)
- **ทำหน้าที่:** รับข้อมูลจากทุกระบบ ตัดสินใจ แล้วสั่งงานกลับไป เป็น "ตัวกลาง" ของทุกการสื่อสารภายในดาวเทียม
- **ของจริงหน้าตาเป็นอย่างไร:** ไม่ต่างจากคอมพิวเตอร์จิ๋วหรือไมโครคอนโทรลเลอร์ — CubeSat ทดลอง/การศึกษาจำนวนมากใช้บอร์ดขนาดเล็กราคาย่อมเยาเป็นจุดตั้งต้น (เช่นตระกูล Raspberry Pi หรือไมโครคอนโทรลเลอร์อื่นๆ) ก่อนจะยกระดับไปเป็นบอร์ดเกรดอวกาศสำหรับภารกิจจริง
- **Analogy:** พนักงานรับสายกลางของบริษัท — ทุกแผนกส่งเรื่องมาที่คนคนนี้ก่อน แล้วคนนี้ค่อยตัดสินใจว่าจะส่งต่อเรื่องไปแผนกไหน

### ⚡ EPS — ระบบไฟฟ้ากำลัง (Electrical Power System)
- **ทำหน้าที่:** ผลิตไฟ (จากแผงโซลาร์เซลล์) เก็บไฟ (แบตเตอรี่) และจ่ายไฟให้ทุกระบบในปริมาณที่เหมาะสม
- **จุดที่ต้องเน้น:** ดาวเทียมไม่มีปลั๊กไฟให้เสียบใหม่ — พลังงานทั้งหมดต้องมาจากแสงอาทิตย์เท่านั้น และต้องบริหารให้พอใช้แม้ตอนอยู่ในเงาโลก (ไม่โดนแดด)
- **Analogy:** เหมือนพาวเวอร์แบงค์ที่ต้องชาร์จตัวเองด้วยแผงโซลาร์ตลอดเวลา แล้วต้องคอยแบ่งไฟให้อุปกรณ์หลายชิ้นพร้อมกันโดยไม่ให้แบตหมด

### 📡 COMM — ระบบสื่อสาร (Communication)
- **ทำหน้าที่:** รับคำสั่งจากพื้นโลก (เรียกว่า **uplink** หรือ "การส่งสัญญาณขึ้น") และส่งข้อมูลกลับลงมา (เรียกว่า **downlink** หรือ "การส่งสัญญาณลง")
- **จุดที่ต้องเน้น:** ดาวเทียมคุยกับโลกได้แค่ตอนบินผ่าน "สถานีภาคพื้นดิน" (ground station) เท่านั้น ไม่ใช่ตลอดเวลา — ถ้าเป็น LEO ที่โคจรเร็ว หน้าต่างเวลาที่คุยได้ในแต่ละรอบอาจสั้นแค่ไม่กี่นาที
- **Analogy:** เหมือนวิทยุสื่อสารที่ใช้คุยได้เฉพาะตอนอยู่ในระยะสัญญาณ พอออกนอกระยะก็ติดต่อไม่ได้จนกว่าจะวนกลับมาใหม่

### 🔬 Payload — อุปกรณ์ภารกิจ
- **ทำหน้าที่:** ส่วนที่ "ทำงานจริง" ตามเป้าหมายของภารกิจ — อาจเป็นกล้องถ่ายภาพ เซนเซอร์วัดค่าต่างๆ หรืออุปกรณ์ทดลองเทคโนโลยีใหม่
- **จุดที่ต้องเน้น:** Payload คือส่วนที่ "แตกต่างกัน" ในดาวเทียมแต่ละภารกิจ ส่วน OBC/EPS/COMM มักออกแบบคล้ายกันในหลายภารกิจ (เพราะทำหน้าที่พื้นฐานเหมือนกันหมด) — payload ต่างหากที่บอกว่าดาวเทียมดวงนี้ "เกิดมาทำอะไร"
- **Analogy:** ถ้า OBC/EPS/COMM คือ "แชสซีรถ" มาตรฐานที่รถทุกรุ่นมีเหมือนกัน payload ก็คือ "อุปกรณ์พิเศษ" ที่ติดตั้งเพิ่มตามงาน (รถดับเพลิงติดปั๊มน้ำ รถพยาบาลติดเปล คือ payload ต่างกันบนแชสซีคล้ายกัน)

**คำศัพท์เสริมที่ควรอธิบายกำกับตรงนี้:** **Telemetry** (เทเลเมทรี) = ข้อมูลสถานะของดาวเทียมเอง (เช่น แบตเหลือเท่าไหร่ อุณหภูมิเท่าไหร่) ที่ส่งลงมาให้ทีมภาคพื้นรู้ว่าดาวเทียม "สบายดีไหม" แยกจากข้อมูลภารกิจ (เช่น ภาพถ่าย) ที่ payload เก็บมา

## 2.3 Interactive Mechanic — สองมุมมองของ CubeSat เดียวกัน

### Mode A: Physical View (โมเดล 3D แบบ exploded ที่มีอยู่แล้ว)
- คลิกแต่ละชิ้นส่วนจริง → เห็น highlight + การ์ดข้อมูล (หน้าที่, ตัวอย่างชิ้นส่วนจริง)
- เป้าหมาย: ให้ผู้เรียนเห็นภาพรวมชิ้นส่วนจริงทั้งหมดของดาวเทียม ว่าแต่ละชิ้นอยู่ตรงไหน หน้าตาเป็นอย่างไร

### Mode B: Functional / Data-flow View (สลับโหมดด้วยปุ่ม toggle)
- ย่อทุกอย่างเหลือ 4 กล่อง: **OBC อยู่ตรงกลาง**, ล้อมรอบด้วย **EPS, Payload, COMM**
- เส้นเชื่อมแยก 2 สี:
  - 🟡 **เส้นพลังงาน** — จาก EPS ไปทุกกล่อง (ทุกระบบต้องใช้ไฟ)
  - 🔵 **เส้นข้อมูล** — ทุกกล่อง ↔ OBC เท่านั้น (Payload, EPS, COMM **ไม่คุยตรงกันเอง** ต้องผ่าน OBC เสมอ)
- **คลิกที่เส้นข้อมูล** → เล่น animation อนุภาคไหลตามเส้น พร้อม caption อธิบายสถานการณ์จริง:

| สถานการณ์ | เส้นทางข้อมูล |
|---|---|
| ทีมภาคพื้นส่งคำสั่ง "ถ่ายภาพ" | COMM รับ uplink → ส่งต่อ OBC → OBC สั่ง Payload ทำงาน |
| Payload ถ่ายภาพเสร็จ | Payload ส่งข้อมูลภาพกลับ OBC → OBC ส่งต่อ COMM → COMM ส่ง downlink ลงพื้นโลก |
| แบตเตอรี่ใกล้หมด | EPS แจ้งสถานะ (telemetry) ไป OBC → OBC ตัดสินใจสั่งลดการใช้พลังงานของ Payload ชั่วคราว |

**Insight สำคัญที่ต้องปลูกฝังผ่าน mechanic นี้:** OBC ไม่ได้ "รู้" อะไรเองเลย มันแค่ตัดสินใจตามข้อมูลที่ระบบอื่นส่งมาบอก — **นี่คือรากฐานตรงที่โมดูล 4 จะสอน if/else** (OBC เจอ "ถ้า...แบตต่ำ...ให้สั่งเซฟโหมด" ก็เพราะมันเป็นแค่ตรรกะง่ายๆ ที่มนุษย์ต้องเขียนสั่งไว้ล่วงหน้า)

## 2.4 Checkpoint

**กิจกรรม "ตามรอยข้อมูล":** ให้สถานการณ์สั้นๆ ที่ไม่เคยเห็นมาก่อน (เช่น "เซนเซอร์วัดอุณหภูมิใน Payload พบว่าร้อนเกินกำหนด") ผู้เรียนต้องคลิกเรียงลำดับ subsystem ที่เกี่ยวข้องให้ถูกลำดับ (Payload → OBC → อาจส่งต่อ COMM เพื่อแจ้งพื้นโลก) — ไม่ใช่ multiple choice แต่เป็น drag-to-sequence เพื่อบังคับให้คิดเป็นเส้นทางจริง

## Glossary สั้นๆ สำหรับโมดูลนี้
| คำศัพท์ | ความหมายแบบเข้าใจง่าย |
|---|---|
| OBC (On-Board Computer) | คอมพิวเตอร์ควบคุมบนดาวเทียม ทำหน้าที่เป็น "สมอง" ตัดสินใจกลาง |
| EPS (Electrical Power System) | ระบบผลิต-เก็บ-จ่ายไฟฟ้าให้ทุกส่วนของดาวเทียม |
| COMM (Communication) | ระบบสื่อสารกับพื้นโลก |
| Payload | อุปกรณ์ที่ทำภารกิจจริงของดาวเทียม (กล้อง เซนเซอร์ อุปกรณ์ทดลอง) |
| Uplink | การส่งสัญญาณ/คำสั่งจากพื้นโลกขึ้นไปหาดาวเทียม |
| Downlink | การส่งข้อมูลจากดาวเทียมลงมายังพื้นโลก |
| Telemetry | ข้อมูลสถานะของดาวเทียมเอง (แบต, อุณหภูมิ, ฯลฯ) ที่ส่งลงมารายงานทีมภาคพื้น |
| Ground Station (สถานีภาคพื้นดิน) | จุดบนโลกที่ใช้ติดต่อสื่อสารกับดาวเทียม |
